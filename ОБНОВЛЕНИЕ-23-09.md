# Обновление от 23.09.2026 — как установить на сервер (Beget)

## Что изменилось

1. **Заблокированные ссылки больше не застревают в «Блокировке».**
   - Ручной выбор «заблокировано» = подтверждение: флаг «ссылка снова доступна» снимается, дело уходит в архив.
   - Кнопка «✅ Ложная тревога — ссылка заблокирована»: дело уходит в архив, и такой же ответ сайта больше не возвращает его обратно.
   - Рядом со ссылкой видно, почему проверка решила, что ссылка открывается (код ответа, адрес, заголовок страницы).
   - Проверка распознаёт страницы-заглушки провайдеров и РКН («доступ ограничен» и т.п.).
   - Можно проверять ссылки через российский прокси (см. шаг 5).
2. **Убраны дубли дат.** Серые поля-копии удалены. Скопировать дату в виде ДД.ММ.ГГГГ — Ctrl+C в поле даты.
3. **Одна колонка «Обращения»** вместо семи: №1, №2, №3… — в каждом «МГС: дата определения, №» → «РКН: дата, №» → статус. Кнопка «+ Повторное обращение» появляется при «отклонено» / «нет реакции» или когда ссылка снова открылась. Колонки «Дата блокировки» и «Повторное решение» убраны (дата блокировки — внутри блока со статусом «заблокировано»). Отчёт Excel, CSV и архив показывают все обращения.
4. **Добавление сайтов.** Любой редактор может добавить сайт в «Поиск по сайтам» (изменять/удалять — по-прежнему только администратор). В строке дела есть кнопка «➕ домен в справочник». Дубли по домену отсекаются (s66.zapret.me и s67.zapret.me — один сайт).

## Установка

Команды ниже — для сервера, где приложение запущено через systemd + gunicorn (так описано в «заметках к развёртыванию»). Замените `/путь/к/приложению` и имя сервиса на свои. Узнать имя сервиса: `systemctl list-units --type=service | grep -i -E "gunicorn|piracy|monitor"`.

1. **Резервная копия данных** (обязательно):
   ```bash
   cd /путь/к/приложению
   cp -r data ../data_backup_2309
   ```
2. **Остановить приложение** (скрипт переноса и работающий сервер не должны писать в data/ одновременно):
   ```bash
   sudo systemctl stop ИМЯ_СЕРВИСА
   ```
3. **Заменить код**: распаковать архив поверх, заменив папки `backend/`, `frontend/`, `tests/`. Папку `data/` и файл `.env` **не трогать** (в архиве их нет).
4. **Перенести обращения в новый формат**:
   ```bash
   source venv/bin/activate        # если используется виртуальное окружение
   python -m backend.migrate_appeals > migrate-check.txt   # диагностика — ничего не меняет
   cat migrate-check.txt
   ```
   В конце должно быть «Пробная проверка целостности: OK». Если там «ОШИБКИ» — **не продолжайте**, пришлите этот файл.
   Затем запись:
   ```bash
   python -m backend.migrate_appeals --apply > migrate-apply.txt
   tail -5 migrate-apply.txt
   ```
   В конце должно быть «Проверка целостности после записи: OK».

   **Как защищены данные при переносе:**
   - перед записью скрипт сам копирует `data/blocking_cases.json` и `data/report_archive.json` в файлы `…before-appeals-ДАТА-ВРЕМЯ` рядом с ними (это в дополнение к вашей копии из шага 1);
   - в каждом деле исходные значения старых полей («№ определения», «Обращение в РКН», «Повторное решение», даты, решения, примечания, дата блокировки) сохраняются целиком в поле `legacy_appeal_fields_backup` — даже если дата где-то разобрана неверно, оригинал остаётся;
   - старые поля не удаляются, поэтому прежняя версия программы тоже продолжает их читать;
   - после записи скрипт перечитывает файлы и сверяет: то же количество дел, те же дела, ни одно другое поле (ссылка, ответчик, примечания, жалобы, скриншоты…) не изменилось. Если что-то не сошлось — он сам возвращает файлы из копий и пишет, что ничего не изменено;
   - примечания скрипт не трогает вообще — номера, записанные в примечаниях, он только показывает в списке для ручного переноса;
   - повторный запуск безопасен: уже перенесённые дела не трогаются.

   Сохраните `migrate-check.txt`: в нём список дел, которые стоит посмотреть глазами — где год даты подставлен автоматически, где дата в тексте номера расходится с датой определения (там текст оставлен как есть), где номера записаны в примечаниях, и заблокированные дела с пометкой «ссылка снова доступна» (у них нажать «Ложная тревога»).

5. **Российский прокси для проверки ссылок** — если сервер стоит не в России. Проверить: `curl -s ipinfo.io/country`. Если ответ не `RU`, добавьте в `.env`:
   ```
   LINK_CHECK_PROXY=http://логин:пароль@адрес-прокси:порт
   ```
   Без этого проверка с зарубежного сервера видит заблокированные РКН сайты как доступные и будет давать ложные тревоги. Рядом со ссылкой в таком случае показывается пометка «(без RU-прокси)».
6. **Запустить и проверить**:
   ```bash
   sudo systemctl start ИМЯ_СЕРВИСА
   sudo systemctl status ИМЯ_СЕРВИСА
   ```
   Открыть «Блокировку» с обновлением страницы без кэша (Ctrl+F5), проверить колонку «Обращения», у s66.zapret.me нажать «Ложная тревога».

## Откат, если что-то пошло не так

```bash
sudo systemctl stop ИМЯ_СЕРВИСА
rm -rf data && cp -r ../data_backup_2309 data
# (или только два файла из автоматических копий скрипта:
#  cp data/blocking_cases.json.before-appeals-ДАТА data/blocking_cases.json
#  cp data/report_archive.json.before-appeals-ДАТА data/report_archive.json)
# вернуть прежние backend/ frontend/ tests/ из старого архива
sudo systemctl start ИМЯ_СЕРВИСА
```
Старые поля данных при переносе не удаляются, поэтому прежняя версия программы продолжит работать с теми же данными.
